<Note>
  This page reflects what `kiosk-js` actually implements today. Deep theming (CSS custom
  properties, a `theme` object, swappable sub-components) is not built yet — see
  [Not yet available](#not-yet-available) below before reaching for any of that.
</Note>

## What you can customise today

### Drop-in widget (`HumainWidget.init()`)

Appearance options are plain JS config values passed to `init()` — there is no CSS-variable layer
underneath them. See [Configuration options](/web/drop-in-widget#configuration-options) for the
full list; the ones that affect appearance are:

| Option | Type | Default | Affects |
|---|---|---|---|
| `primaryColor` | `string` (hex) | `"#0E50BD"` | FAB background, header background, send button, user message bubbles |
| `theme` | `"light"` \| `"dark"` \| `"auto"` | `"auto"` | Background/surface/border/text colours. `"auto"` follows `prefers-color-scheme` |
| `zIndex` | `number` | `9999` | Stacking order of the widget |
| `position` | `"bottom-right"` \| `"bottom-left"` | `"bottom-right"` | Corner placement |

```javascript
HumainWidget.init({
  credential: "hk_live_your_credential_here",
  primaryColor: "#7c3aed",
  theme: "auto",
})
```

Everything else about the widget's look — spacing, radius, shadows, fonts, bubble colours — is
currently fixed and not configurable.

### React (`<KioskChat>`)

`@humain/kiosk-js/react` exports a `KioskChat` component that renders its own chat UI with
hardcoded inline styles. The only style hooks it accepts are `className` and `style`, which apply
to the **outer container only** — they don't reach the header, bubbles, or input row inside it:

```tsx
import { KioskChat } from "@humain/kiosk-js/react"

<KioskChat
  credential="hk_live_your_credential_here"
  className="my-chat-wrapper"
  style={{ maxWidth: 420 }}
/>
```

### Vue (`<KioskChat>`)

The Vue `KioskChat` component currently accepts no style-related props at all (`credential`,
`mode`, `placeholder`, `title`, `initialMessage` only). Its internal styles are fixed, same as the
React version.

## Not yet available

The following do **not** work despite sometimes appearing in examples elsewhere — there is no
implementation behind them yet in `kiosk-js`:

- **CSS custom-property overrides.** The widget's shadow-DOM styles do set internal variables like
  `--hk-primary` and `--hk-bg`, but they're computed from the JS config at mount time and written
  directly onto `:host` — they never read an externally-set `:root` value. Setting `--hk-primary`
  (or any `--hk-*` variable) on your page's `:root` has no effect on the widget.
- **A `theme` object.** `theme` on `WidgetConfig` is a string union (`"light" | "dark" | "auto"`),
  not an object. There is no `primary` / `background` / `surface` / `radius` / `dark: {...}`
  theme-object API on the widget, `<KioskChat>`, or `HumainKioskClient`.
- **Custom component slots.** There is no `components` prop on React's `<KioskChat>` and no named
  slots on Vue's `<KioskChat>`. `MessageBubble`, `Header`, `InputArea`, `SendButton`,
  `TypingIndicator`, and `EmptyState` are not exposed for replacement — the chat UI is rendered
  as a single fixed component in both frameworks.

If your integration needs full visual control beyond `primaryColor` / `theme` / `zIndex` today,
build your own chat UI against the underlying `HumainKioskClient` / `Session` APIs (see
[Vanilla JS](/web/vanilla-js)) instead of the drop-in widget or `<KioskChat>`.
